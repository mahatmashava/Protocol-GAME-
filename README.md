Project:  PROTOCOL
1. Executive Summary
 Protocol is an agentic, competitive "Hacker-Sim" game where players architect autonomous AI systems (Agents) to dominate a simulated network known as the Maelstrom.
Moving beyond simple prompting, players design Behavior Trees that are compiled into JSON logic and executed in a low-cost, high-scale deterministic engine. Success is measured by Unique IP Loads, Exfiltrated Data Credits, and Network Uptime.

2. Core Mechanics
A. The Agent Forge (Architecture)
Players do not "play" the game in real-time. Instead, they use an LLM-assisted workspace to build an agent's logic.
Nodes: Draggable logic blocks (Recon, Exploit, Defense, Sabotage).
Compute Credits (CC): A resource limit that prevents over-powered agents.
The Realization: The Forge compiles the visual tree into a JSON Logic Script, ensuring zero API costs during the actual battle.
B. The Maelstrom (The Battlefield)
A persistent environment containing 10,000 Synthetic User Intents and vulnerabilities.
Clustering: User inputs are grouped into "Gravity Wells" (High-value targets).
The Vector Clash: Scoring is determined by the mathematical distance between an Agent's output and the User's intent.
C. Adversarial Interaction
Agents can detect and counter other players autonomously:
Shadow Pivot: Automatically shifting to a new niche if a competitor is detected.
Signal Jammer: Actively lowering the relevance score of nearby rivals.
Logic Bombs: Latent defensive nodes that trigger upon being hacked.

3. Technical Architecture
The "Compile-Once, Run-Many" Model
To maintain scalability, the game avoids per-turn LLM calls:
Drafting: Player uses an LLM to generate the JSON Logic (One-time cost).
Validation: The server validates the JSON against a strict Schema to prevent real-world injections.
Simulation: The Game Engine executes the logic using Vector Math (Cosine Similarity) and deterministic state machines.

{
  "agent_id": "Ghost_Root_01",

    { "node": "Port_Scanner", "on_fail": "Abort" },
    { "node": "Script_Injection", "params": { "stealth": "high" } }
  ]
}

1. Technical API Specification: Marketplace Validation
To prevent a "Zero-Day" listing from being a real-world exploit, the marketplace uses a Validation & Sandbox API. This ensures the JSON logic is strictly for in-game execution.
API Endpoint: /v1/marketplace/validate-logic

* Method: POST
* Authentication: Bearer (JWT) + Syndicate-ID
* Payload Schema: JSON Schema is used to enforce strictly defined game operands. [1, 2] 

Validation Workflow

   1. Static Schema Analysis: Rejects any keys not present in the game’s official logic_manifest. This prevents Injection Attacks.
   2. Credit Check: Verifies that the sum of all node costs (spent_cc) does not exceed the agent's capacity.
   3. Sanitization: All strings are parsed to remove potential script tags (XSS) or SQL commands.
   4. Sandbox Simulation: The code is executed in a Web Worker or Isolate-VM to ensure it doesn't access the server's file system or external network.
   5. Performance Profiling: If the logic takes >10ms to resolve a single turn, it is flagged as "Inefficient" or a potential DoS (Denial of Service) attempt. [1, 3, 4, 5, 6]

* Function: Deletes the "Digital Footprint" after an attack.
   * Logic: Increases the time it takes for a rival player to find your Home IP on the War Map.
